# 《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》精读笔记

> 原文：Patrick Lewis 等（Facebook AI Research / UCL / NYU），NeurIPS 2020。
> 本笔记为中文学习笔记，以要点归纳和个人解读为主，不是原文译文；公式、完整实验表格与细节请以原文为准。

## 一句话结论

RAG 把**参数化记忆**（预训练的 seq2seq 模型 BART）和**非参数化记忆**（维基百科的稠密向量索引，由 DPR 检索器访问）组合成一个端到端训练的概率模型。它在开放域问答上刷新了最佳成绩，生成的内容更具体、更多样、更符合事实，而且换掉索引就能更新知识，不需要重新训练。

## 1. 动机

- 预训练语言模型能把大量知识存进参数，但有三个问题：难以扩展或修改知识；难以解释依据；会产生幻觉。
- 已有的"参数 + 检索"混合模型（REALM、ORQA）只做了**抽取式**问答。
- 本文把混合记忆带到通用的 seq2seq 生成上，提出一套**通用的微调配方**。

## 2. 方法

### 2.1 两个组件

| 组件 | 实现 | 角色 |
|---|---|---|
| 检索器 p_η(z \| x) | DPR 双塔：BERT 文档编码器 + BERT 查询编码器，打分为两个向量的内积 | 给定输入 x，返回 top-K 文档的分布 |
| 生成器 p_θ(y_i \| x, z, y_1:i-1) | BART-large（约 4 亿参数），输入 x 与文档 z 直接拼接 | 基于输入和文档逐 token 生成 |

- top-K 检索是一个最大内积搜索问题，可以在亚线性时间内近似求解。
- 检索器用 DPR 预训练权重初始化（DPR 本身用 NQ 和 TriviaQA 的检索监督训练过）。

### 2.2 两种边缘化方式

把检索到的文档 z 当作**隐变量**，对它做边缘化：

- **RAG-Sequence**：整句话都用同一篇文档生成。先对每篇文档算出整句的概率，再按检索概率加权求和。
- **RAG-Token**：每个 token 都可以依据不同的文档。每一步先对 top-K 文档加权得到下一个 token 的分布，然后继续下一步。这让答案可以**拼接多篇文档的信息**。
- 对分类任务（输出长度为 1），两者等价。

### 2.3 训练

- 不给"该检索哪篇文档"的监督，只最小化目标序列的负边缘对数似然。
- **文档编码器和索引保持冻结**，只微调查询编码器和 BART。作者发现，像 REALM 那样周期性重建索引并非必要。

### 2.4 解码

- **RAG-Token**：本质上就是标准的自回归生成，直接用束搜索（beam search）。
- **RAG-Sequence**：似然不能按 token 分解，所以对每篇文档分别做束搜索，得到候选集合。
  - **完整解码（Thorough Decoding）**：候选如果没出现在某篇文档的 beam 里，就额外做一次前向计算补上它的概率，再汇总。
  - **快速解码（Fast Decoding）**：直接把没出现的候选概率近似为 0，省去额外计算。

## 3. 实验设置

- 知识源：2018 年 12 月的维基百科，切成 100 词的片段，共约 2,100 万篇"文档"；用 FAISS 的 HNSW 近似索引。
- 训练时 K 取 5 或 10，测试时的 K 用开发集调。
- 任务一览：

| 任务类型 | 数据集 | 说明 |
|---|---|---|
| 开放域问答 | NQ、TriviaQA、WebQuestions、CuratedTrec | 指标为精确匹配（EM）；WQ 和 CT 数据量小，从 NQ 模型初始化 |
| 生成式问答 | MS-MARCO NLG v2.1 | 不用官方给的标准段落，当作开放域问题 |
| Jeopardy 问题生成 | SearchQA 划分 | 给定答案实体，生成一句"事实型线索"；指标为 Q-BLEU-1，另加人工评估 |
| 事实核查 | FEVER（3 分类 / 2 分类） | 不使用证据检索的监督 |

## 4. 主要结果（挑重点）

### 4.1 开放域问答

- 在四个数据集上都达到当时最佳（TQA 指与 T5 可比的划分）。例如 NQ 上 RAG-Sequence 为 44.5 EM，高于 DPR 的 41.5 和 REALM 的 40.4。
- 不需要 REALM 或 T5+SSM 那种昂贵的"显著片段遮盖"预训练，也不需要重排器或抽取式阅读器。
- **生成式的独特优势**：文档里只有线索而没有原文答案时也能帮上忙。在 NQ 上，即使正确答案不在任何检索文档中，仍有 11.8% 能答对，而抽取式模型在这种情况下只能是 0。

### 4.2 生成式问答（MS-MARCO）

RAG-Sequence 比 BART 高约 2.6 BLEU 和 2.6 Rouge-L，已接近使用标准段落的最佳模型。定性观察是幻觉更少。

### 4.3 Jeopardy 问题生成

- RAG-Token 优于 RAG-Sequence，两者都优于 BART。
- 人工评估 452 对样本：认为 BART 更符合事实的只占 7.1%，认为 RAG 更符合事实的占 42.7%；在具体性上 RAG 也大幅领先。
- **参数记忆与检索记忆的协作**（Hemingway 例子）：生成 "The Sun Also Rises" 的第一个 token 时，模型高度依赖提到该书的文档；第一个 token 之后，文档后验变平，说明书名剩下的部分由 BART 参数里的知识补全。可以理解为检索负责"点拨"，参数负责"想起来"。

### 4.4 FEVER

- 3 分类上与使用中间检索监督的复杂流水线相差不到 4.3%；2 分类上与使用标准证据的 RoBERTa 相差 2.7%。
- 检索质量：第 1 篇检索结果来自标准证据文章的比例为 71%，前 10 篇中包含标准证据文章的比例为 90%。

### 4.5 其他分析

- **多样性**：不同 trigram 的占比 RAG-Sequence > RAG-Token > BART，而且不需要专门的多样性解码。
- **检索消融**：冻结检索器会让所有任务变差；换成 BM25 时只有 FEVER 更好（主张以实体为中心，适合词项匹配），其他任务，尤其是开放域问答，都是可学习的稠密检索更好。
- **索引热替换**：用 82 位在 2016 到 2018 年间换届的世界领导人做测试。索引和问题年份匹配时正确率约 70% 和 68%；错配时只有 12% 和 4%。**换索引就能更新知识。**
- **检索篇数**：测试时增加 K，RAG-Sequence 的问答效果单调提升；RAG-Token 在 K≈10 时达到峰值。

## 5. 相关工作定位

- 相比只做单任务检索的工作：用**一个**检索式架构统一多个任务。
- 相比 GPT-2、BART、T5 等通用架构：在它们之上加一个可学习的检索模块。
- 相比记忆网络：记忆是**原始文本**，人可以读（可解释），也可以写（直接编辑索引就能改知识）。
- 与"检索再编辑"的区别：重点不在轻度修改一个检索结果，而在**聚合多个检索结果**，并且检索器是隐式学出来的。

## 6. 讨论与社会影响

- 未来方向：两个组件是否可以从零开始联合预训练；参数记忆和非参数记忆如何更好地交互。
- 正面影响：更有事实依据、幻觉更少、可控、可解释。
- 风险：外部知识源本身不可能完全真实、无偏；和其他语言模型一样可能被滥用于虚假内容、冒充他人、垃圾信息等。

## 7. 对本仓库 web-search-agent-go 的启示（个人解读）

- web-search-agent 相当于把 RAG 的"非参数记忆"从静态维基索引换成了**实时联网搜索**。好处是天然具备论文里"索引热替换"的特性，知识始终是最新的。
- RAG-Token 那种"不同片段依据不同文档"的思想，对应到 Agent 场景，就是**多次搜索、聚合多个 observation**；本仓库用 errgroup 并行执行多个搜索调用，正是这个方向。
- 论文说明检索只负责"点拨"，所以即使检索结果不完全命中，模型也可能答对。反过来，验收时不能只看"答案是否出现在检索结果里"，还需要事实层面的断言。
