# 《LLM Powered Autonomous Agents》精读笔记

> 原文：Lilian Weng，Lil'Log，2023-06-23，https://lilianweng.github.io/posts/2023-06-23-agent/
> 本笔记为中文学习笔记，以要点归纳和个人解读为主，不是原文译文；原文中的提示词模板、示例对话与图表请直接查阅原文。

## 一句话结论

以 LLM 为"大脑"的自主 Agent 由三块能力支撑：**规划**、**记忆**、**工具使用**。文章按这三块梳理了代表性方法，再用几个案例和 PoC 项目说明落地时的挑战：上下文有限、长程规划难、自然语言接口不可靠。

## 0. 系统总览

| 组件 | 子能力 | 作者的理解 |
|---|---|---|
| 规划 | 子目标分解 | 把大任务拆成可管理的小步骤 |
| 规划 | 反思与改进 | 对历史行动做自我批评、吸取教训 |
| 记忆 | 短期记忆 | 上下文学习本身就是在用短期记忆 |
| 记忆 | 长期记忆 | 外部向量库加快速检索，实现"近乎无限"的保存与回忆 |
| 工具使用 | 调用外部 API | 补上权重里没有的信息：实时数据、代码执行、私有数据源等 |

## 1. 组件一：规划

### 1.1 任务分解

- **CoT（思维链）**：让模型"一步一步想"，用更多推理时计算把难题拆成简单步骤，同时让思考过程可解释。
- **ToT（思维树）**：每一步生成多个候选想法，形成一棵树，用 BFS 或 DFS 搜索，每个状态由提示分类器或投票评估。
- 三种分解方式：简单提示（"XYZ 的步骤是……"）、任务特定指令（如"先写故事大纲"）、人工输入。
- **LLM+P**：把长程规划外包给经典规划器。LLM 先把问题翻译成 PDDL，规划器求解后再翻译回自然语言。前提是领域 PDDL 和规划器都现成，这在机器人领域常见，但在其他领域不多见。

### 1.2 自我反思

- **ReAct**：把动作空间扩展为"任务动作 + 自然语言推理"，形成 Thought → Action → Observation 的循环。在知识密集型任务和决策任务上都优于去掉 Thought 的纯 Act 基线。
- **Reflexion**：在 ReAct 之上加动态记忆和自我反思。
  - 用启发式规则判断轨迹是否该终止：一类是"低效"（太久没成功），一类是"幻觉"（连续执行相同动作并得到相同观察）。
  - 反思内容由两个 few-shot 示例（失败轨迹 → 理想反思）引导生成，最多保留 3 条放进工作记忆。
  - 在 AlfWorld 中，幻觉比低效规划更常见。
- **CoH（Chain of Hindsight）**：把带人类反馈、按奖励排序的一系列历史输出拼成序列做 SFT，让模型学会"顺着改进趋势产出更好的结果"。为防过拟合，加入预训练似然正则；为防止模型走捷径直接照抄，随机遮掉 0%–5% 的历史 token。
- **AD（Algorithm Distillation）**：同样的思想用在强化学习上。把多个回合的学习历史拼起来喂给模型，让它学会"学习过程"本身，而不是某个具体策略。需要 2–4 个回合长度的上下文才能涌现上下文内强化学习；效果接近在线方法 RL²，学习速度明显快于专家蒸馏等基线。

## 2. 组件二：记忆

### 2.1 人脑记忆类比

| 人脑记忆 | 特点 | 对应到 LLM Agent |
|---|---|---|
| 感觉记忆 | 持续几秒，含视觉、听觉、触觉 | 对原始输入学到的嵌入表示 |
| 短期 / 工作记忆 | 约 7 项，持续 20–30 秒 | 上下文学习，受上下文窗口限制 |
| 长期记忆（外显：情景、语义；内隐：技能） | 容量近乎无限 | 外部向量库，查询时检索 |

### 2.2 最大内积搜索（MIPS）与近似最近邻（ANN）

外部记忆的常见实现：把信息向量化存进支持快速最大内积搜索的库，用近似最近邻算法牺牲少量精度换取大幅提速。

| 算法 | 核心思想（一句话） |
|---|---|
| LSH | 设计哈希，让相似项大概率落进同一个桶 |
| ANNOY | 随机投影树组成的森林，每个非叶节点是一个切分超平面，多棵树一起搜索再汇总 |
| HNSW | 分层小世界图：上层做长距离跳跃，下层精细搜索 |
| FAISS | 向量量化：先粗量化找候选簇，再在簇内细量化 |
| ScaNN | 各向异性量化，让量化后的内积尽量保持原始的相对大小 |

## 3. 组件三：工具使用

- **MRKL**：神经符号架构，LLM 充当路由器，把请求分派给"专家模块"（可以是神经网络，也可以是计算器、汇率换算、天气 API 等符号工具）。实验发现，LLM 很难从文字题里稳定抽取算术参数，说明"何时用、怎么用工具"取决于 LLM 本身的能力。
- **TALM / Toolformer**：微调模型学会调用 API。训练数据的筛选标准是：插入某个 API 调用标注后，输出质量是否变好。
- **ChatGPT 插件 / Function Calling**：工具能力的工程化落地。
- **HuggingGPT**：ChatGPT 当任务规划器，分四个阶段：任务规划 → 模型选择 → 任务执行 → 汇总响应。挑战在于推理轮次多导致速度慢、依赖长上下文，以及 LLM 输出和外部服务的稳定性。
- **API-Bank**：53 个常用 API、264 段对话、568 次调用。评测分三个层级：
  - Level-1：给定 API 描述，能否正确调用；
  - Level-2：能否自己检索到合适的 API 并读懂文档；
  - Level-3：面对模糊需求，能否规划多次调用。

## 4. 案例研究

### 4.1 科学发现 Agent

- **ChemCrow**：配备 13 个专家设计的化学工具，按 ReAct 格式工作。有意思的结论是：用 LLM 当裁判时，它和 GPT-4 差不多；但专家人工评估显示 ChemCrow 明显更好。这说明在需要深度专业知识的领域，**LLM 自评并不可靠**。
- **Boiko et al. 2023**：能联网、读文档、执行代码、调用实验机器人 API。作者特别讨论了风险：用已知化学武器清单测试，11 个请求中有 4 个被接受（36%）。在被拒绝的 7 个中，5 个是在网络搜索之后拒绝的，2 个是仅凭提示就拒绝的。

### 4.2 生成式智能体模拟（Generative Agents）

25 个由 LLM 驱动的角色在一个类似《模拟人生》的沙盒里生活、互动。架构要点：

- **记忆流**：用自然语言记录所有经历的外部数据库。
- **检索**：按"近期性、重要性（让模型自己打分）、相关性"三者综合排序。
- **反思**：定期把记忆归纳成更高层的推断，指导未来行为。注意这和前文的"自我反思"不是一回事。
- **规划与反应**：结合反思和环境信息生成行动计划。
- 涌现出信息扩散、关系记忆、组织聚会等社会行为。

### 4.3 PoC 项目

- **AutoGPT**：让人看到"LLM 当主控"的可能性，但自然语言接口带来大量可靠性问题，代码很大一部分都在做输出格式解析。原文附有它的完整系统提示（目标、约束、命令列表、资源、自我评估，并要求 JSON 格式回复），请查阅原文。
- **GPT-Engineer**：根据自然语言需求生成整个代码仓库。流程是先澄清需求（列出不明确之处，一次只问一个问题），再切换到写代码模式。原文附有完整的对话示例。

## 5. 挑战

1. **上下文长度有限**：历史信息、详细指令、API 上下文和返回结果都要挤在里面；反思类机制尤其需要长上下文。向量检索的表达力也不如全注意力。
2. **长程规划与任务分解难**：遇到意外错误时，LLM 调整计划的能力不如人类的试错学习稳健。
3. **自然语言接口不可靠**：格式错误、偶尔不遵循指令，所以 Demo 代码大量在做输出解析。

## 6. 对本仓库 web-search-agent-go 的启示（个人解读）

- 本仓库的 `internal/react` 正是 ReAct 循环的实现。Reflexion 的"连续相同动作 + 相同观察 = 幻觉"这一启发式，可以直接用来检测 Agent 是否在重复同一个搜索。
- 挑战 3（接口不可靠）对应本仓库对模型输出的结构化解析与失败兜底，这也是 Go 版本严格区分 answer 和 action 的原因。
- ChemCrow 的教训说明，验收不能只靠 LLM 自评，程序化断言和黄金回放更可信。
